# 诸神寰宇 · noname-Nihilism-Oracle

## 扩展内容

- 武将与技能：包含诸神寰宇、烬灭古域（含光阴长河、万象归一）、归墟之地、神话再临、一将成名、文德武备、门阀士族、上兵伐谋、兵势篇、璀璨星河、限定专属、移动版等12个加载入口。
- 专属机制：包含绝恒技、状态技、亡灵技等设计，游戏内的「帮助 → 诸神寰宇」提供名词说明。
- 配套资源：武将立绘、技能与阵亡语音、皮肤、背景图片和音乐。
- 扩展设置：本体武将开关、AI相关设置、背景与前缀显示设置；信息栏可查看本次更新及修改武将。

## 安装与更新

本仓库需要配合无名杀本体使用。当前按 **1.11.6.1** 的接口维护，其他本体版本尚未在本仓库中验证。

1. 打开 [Releases 下载页](https://github.com/NihilismOracle/noname-Nihilism-Oracle/releases/latest)，选择显示为 **诸神寰宇1.0.5.zip** 的附件。GitHub实际下载名为 **ZhuShenHuanYu1.0.5.zip**，下载后可改为 **诸神寰宇1.0.5.zip**。
2. 支持扩展 ZIP 导入的客户端可直接导入该安装包。手动安装时，将压缩包内容解压到本体的 **`extension/诸神寰宇/`** 目录。
3. 按所用客户端的扩展管理流程启用「诸神寰宇」，然后重启游戏。
4. 更新已有安装时，先备份旧目录，再用新版本文件替换对应文件。

安装包打开后的根目录直接包含 `info.json`、`extension.js`、`packages.js` 和各资源目录，不包含 `noname-Nihilism-Oracle-main/` 等外层目录。安装包中不含测试、开发脚本或 Git 相关文件。

目录结构应为：

```text
<无名杀本体目录>/
├── noname.js
└── extension/
    └── 诸神寰宇/
        ├── extension.js
        ├── packages.js
        ├── info.json
        ├── character/
        ├── extension/
        ├── image/
        └── audio/
```

GitHub 的 **Code → Download ZIP** 与 Release 自动附带的 **Source code (zip)** 是源码归档，仍带仓库名外层目录。安装请选择显示为 **诸神寰宇＋版本号.zip** 的附件；其实际下载名使用 **ZhuShenHuanYu＋版本号.zip**。手动安装的目录仍须叫 `诸神寰宇`，资源路径和模块导入依赖上面的目录层级。

## 1.0.5 发布方式更新

提供无外层目录的安装 ZIP、SHA-256 校验文件及标签自动发布流程。GitHub会过滤附件文件名中的中文，因此使用拼音下载名与中文显示名；本地构建文件保留中文名。发布前自动核对远端附件，技能规则不变。

## 1.0.3 技能修复摘要（历史版本）

- 审时保持1点伤害及交给一张牌，每张赠牌独立追踪并最多结算一次；返乡补摸四张并强制觉醒。
- 相胥取消隐藏次数限制并修复弃牌分支；清靓取消隐藏次数限制，第二项弃置一种花色的所有手牌；定措修复颜色、弃牌及伤害选择。
- 修复酒池／崩坏、暗箭、怠宴、权术、滔乱和劫营的触发条件与结算，使使用、打出和状态增益符合已确认规则。
- 唤魂分别复制体力值与上限，采用化身式描述；替换、重铸独立在准备阶段事件内结算，并等待所有选择结束。用户反馈的客户端阶段显示问题仍需实机复核。
- 修正连破、三种战车与督粮的阶段／回合边界，明确智迟逐张选择是否无效。

本次新增32项局部回调验证与原有26项回归测试通过；新增验证脚本保留在维护工作目录，不随扩展发布。尚未完成完整客户端对局验证。

## 1.0.2 技能修复摘要（历史版本）

| 技能 | 本次修复后的规则 |
| --- | --- |
| 墟司马伷 · 才望 | 响应双方牌颜色相同，可弃置对方一张手牌或装备牌；颜色不同，回复1点体力或摸一张牌，对方无牌也可触发。两张均无色视为相同，保留〖纳降〗将弃置改为获得的联动。 |
| 墟陈到 · 往烈 | 每回合首张伤害牌无距离限制；在任意时段使用伤害牌指定目标后，此牌不能被响应，额外结算X次。X＝自身已损失体力＋所有目标中最大的已损失体力＋1。 |
| 墟SP袁术 · 庸肆 | 准备阶段摸X张牌后，可重铸至多X张手牌。重铸伤害类牌后，本回合使用【杀】无距离限制且次数上限增加相应数量；加成持续整个回合，不改变其他机制使用的攻击范围。 |

往烈的「额外结算」在原有次数上累加：例如自身已损失2点体力，目标中最高已损失3点，额外结算6次；若原本结算1次，则共结算7次。

完整技能描述保存在各武将包的 `translate.js`；本次具体改动与历史记录见[更新日志](更新日志.md)。

## 开发与验证

修改技能时同步检查相应 `skill.js`、`translate.js`，以及涉及的动态描述、武将注册和资源引用。

在仓库根目录运行回归测试（已在 Node.js 24 验证，无需安装额外依赖）：

```sh
node --experimental-vm-modules --test tests/skill-regressions.cjs
```

现有26项测试直接执行技能回调，覆盖才望的颜色与响应方向、〖纳降〗、往烈的次数与目标、庸肆的持续时间等。测试使用简化引擎环境；通过回归测试与语法检查不代表已通过实机对局验证。本次修复尚未进行游戏启动、实机对局或联机验证。

### 绝恒技与安璟的维护入口

`extension/skillProtection.js` 在武将包注册前保存带 `NihilismSkill` 标签的可信定义，在运行时保护原技能ID、子技能及发动事件；`extension/arenaReady.js` 继续处理专属获得资格和移除、封禁等操作。新增绝恒技沿用标签登记，技能运行时缓存应放在模块私有变量或角色存储中，避免改写已登记的规则定义。帮助词条位于 `extension/help/help.js`。

安璟的事件排序、无限状态、原生休整与阵营胜负处理集中在 `character/Nihilism/anjing.js`，技能入口和描述仍位于同目录的 `skill.js`、`translate.js`。验证以无名杀1.11.6.1为基准；当前验证覆盖真实引擎局部结算与模式胜负入口，完整客户端、联机及其他扩展直接重写引擎的场景需分别验证。

### 日常修改与统一发布

1. 日常修改先更新实现、技能描述及《更新日志.md》的“未发布”记录（标题格式：`YYYYMMDD（未发布，基于上次正式版本号）`），完成相关验证后推送GitHub。新增测试、mock和临时验证文件仅保留在仓库外，不上传，也不进入安装包。
2. 公告和版本信息由维护者确认统一发布时再更新；小修改不自动改《更新公告.md》、版本号、生成的更新摘要及版本武将列表，也不推送版本标签或触发Release。主分支可能包含尚未正式发布的改动。
3. 准备统一发布时，以**上次已正式发布的版本标签及其公告、版本信息**为基线，对比当前代码和累计日志，只汇总相对基线实际新增、修改和修复的内容；合并重复条目，剔除已撤回改动，不重复描述未变化的历史内容。先将完整公告及拟定版本信息交维护者确认。
4. 确认后，再更新《更新公告.md》、日志中的正式发布记录、README版本/日期，以及 `extension/versionCharacters.js` 中实际新增或修改的武将。公告标题格式为 `YYYYMMDD（扩展版本，适配无名杀 本体版本）`。
5. 运行下面的同步命令生成 `extension/updateInfo.js` 并同步 `info.json`；核对 `packages.js` 与 `extension.js` 的展示和引用。它们读取同一份生成数据，无需重复写死版本号。
6. 核验发布改动与附件后提交、推送对应 `v版本号` 标签，等待「发布扩展安装包」工作流成功，并确认Releases中出现正确安装包。已公开版本不自动覆盖。

```sh
# 维护者确认统一发布、更新公告后，再同步生成文件
node scripts/sync-update-info.cjs

# 只检查正式发布信息是否同步；允许日志累计未发布段，不修改文件
node scripts/sync-update-info.cjs --check
```

`extension/updateInfo.js` 是生成文件，请修改《更新公告.md》后重新运行脚本。

本地构建安装包（Python 3.11或更高版本）：

```sh
node scripts/sync-update-info.cjs --check
python scripts/build-release.py
```

结果位于 `dist/`，本地文件名为 `诸神寰宇{版本号}.zip`；`dist/upload/` 内是内容相同的拼音文件名副本，供GitHub发布使用。构建会检查ZIP根目录、文件完整性与版本一致性，发布时进一步核对远端附件；`dist/` 已忽略，不提交压缩包到源码仓库。
